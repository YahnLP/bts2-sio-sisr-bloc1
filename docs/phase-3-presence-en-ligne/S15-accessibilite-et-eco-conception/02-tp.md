## Partie A – Audit manuel (≈ 40 min)

Ouvre `accessibilite_defauts.html` dans un navigateur.

1. **Clavier.** Sans utiliser la souris, fais défiler les éléments avec la touche Tab. Peut-on atteindre et activer le bouton « Envoyer » ? ______
2. **Zoom.** Agrandis la page à 200 %. Le contenu reste-t-il lisible et complet ? ______
3. **Lecture du code.** Relève dans le code tous les défauts que tu repères (liste libre, au moins cinq).
4. **Contraste.** Le texte « Réponse sous deux jours ouvrés » est en `#999999` sur fond blanc. Calcule le rapport de contraste (outil de contrôle de contraste ou formule du cours) et dis s'il est suffisant pour du texte courant. ______

**J'anticipe.** Combien de défauts penses-tu trouver ? Lesquels l'outil automatique manquera-t-il probablement ? ______________________

<summary>Éléments de réponse</summary>

Le « bouton » est un `div` : il n'est pas atteint par Tab. Défauts à relever : voir le corrigé de l'enseignant. Le contraste calculé est **bien inférieur** à 4,5:1.

## Partie B – Audit automatique et correction (≈ 40 min)

1. Installe `jsdom` (`npm install jsdom`) puis lance `node audit.js accessibilite_defauts.html`. Combien de problèmes sont détectés ? Recopie-les.
2. Relie chaque problème à l'un des **quatre principes** (perceptible, utilisable, compréhensible, robuste).
3. Compare avec ta liste de la partie A : quel défaut **l'outil ne voit-il pas** ? Pourquoi ?
4. **Corrige** la page (copie `accessibilite_defauts.html` sous un autre nom). Relance l'outil jusqu'à « Aucun problème détecté ». Corrige aussi le contraste et vérifie le **clavier** à la main.
5. Lance l'outil sur `salles.html` (le portail). Que conclus-tu ?

**J'anticipe.** L'outil donnera-t-il « aucun problème » sur la page du portail ? Est-ce suffisant pour déclarer le portail accessible ? ______

<details markdown="1">
<summary>Éléments de réponse</summary>

Sept problèmes sont détectés ; le contraste n'en fait pas partie. Un résultat « aucun problème » sur cinq contrôles ne prouve pas la conformité : il reste le clavier, le zoom, le sens des textes alternatifs, le lecteur d'écran, et beaucoup d'autres critères.

</details>

## Partie C – Le contraste, par le calcul (≈ 20 min)

Pour une couleur `#RRGGBB`, chaque composante *c* (entre 0 et 1) est d'abord transformée : si *c* ≤ 0,03928, *c*/12,92 ; sinon ((*c* + 0,055) / 1,055)^2,4. La luminance est L = 0,2126 R + 0,7152 V + 0,0722 B.

1. Écris (en Python ou JavaScript) une **fonction** qui calcule le rapport de contraste de deux couleurs.
2. Calcule le rapport pour : `#999999` sur `#ffffff` ; `#595959` sur `#ffffff` ; `#767676` sur `#ffffff` ; `#ffffff` sur `#1f4e79`. Lesquels respectent le minimum de 4,5:1 ?
3. Le gris `#767676` te semble-t-il un choix prudent pour un texte de 14 pixels ? Pourquoi garder une marge ?

2. Quelle est l'**économie** apportée par la compression, en pourcentage ?
3. Combien de **requêtes** faut-il pour afficher la page (hors `favicon.ico`) ?
4. Le journal de S13 comptait **381 pages vues en une semaine**. En supposant le même trafic toute l'année (52 semaines) et **sans cache**, calcule le volume annuel transféré par les pages vues avec les fichiers compressés.
