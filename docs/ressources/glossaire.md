# Glossaire

Les mots techniques du bloc 1 de deuxième année (projet, programmation web, présence en ligne, support avancé), expliqués simplement. Dans les pages du site, **passe la souris sur un sigle** (VLAN, DHCP, GPO…) : sa définition s'affiche.

> [!NOTE]
> Les termes déjà vus en première année sont repris dans le glossaire du dépôt `bts1-sio-sisr-bloc1`.

La colonne « Vu en » indique la séance où le mot apparaît pour la première fois dans le cours.

| Terme | Sigle | Anglais | Définition | Vu en |
|---|---|---|---|---|
| **Accessibilité numérique** |  | *digital accessibility* | Capacité d'un site à être utilisé par le plus grand nombre de personnes, quelles que soient leurs capacités. | S15 |
| **Agent utilisateur** |  | *user-agent* | Texte par lequel un navigateur ou un robot se présente au serveur. | S13 |
| **Approche agile** |  | *agile approach* | On avance par petites livraisons successives et on s'adapte aux retours. | S03 |
| **Approche prédictive** |  | *predictive approach* | On planifie tout au départ, puis on suit le plan (cycle en V, cascade). | S02 |
| **Balise sémantique** |  | *semantic element* | Balise HTML qui décrit le rôle d'un bloc (en-tête, navigation, contenu principal) et pas seulement son aspect. | S06 |
| **Bastion** |  | *bastion host* | Serveur d'entrée surveillé par lequel passent les accès d'administration. | S16 |
| **Branche** |  | *branch* | Ligne de modifications parallèle à la version principale, pour travailler sans la casser. | S10 |
| **Bureau à distance** | RDP | *remote desktop protocol* | Protocole d'affichage et de contrôle à distance d'un poste Windows. | S16 |
| **Bureau d'enregistrement** |  | *registrar* | Société auprès de laquelle on loue un nom de domaine. | S11 |
| **Carnet de produit** |  | *product backlog* | Liste ordonnée de tout ce qu'on veut dans le produit. | S03 |
| **Catalogue de services** |  | *service catalog* | Liste publiée de ce que le service informatique propose, avec délais, disponibilité et mode de demande. | S17 |
| **Certificat** |  | *certificate* | Fichier signé par une autorité qui prouve l'identité d'un site et permet le chiffrement HTTPS. | S11 |
| **Chemin critique** |  | *critical path* | Suite de tâches qui détermine la durée minimale du projet : tout retard dessus retarde le projet. | S02 |
| **Clé étrangère** |  | *foreign key* | Colonne qui renvoie à la clé primaire d'une autre table et garantit la cohérence entre les deux. | S09 |
| **Clé primaire** |  | *primary key* | Colonne qui identifie de façon unique chaque ligne d'une table. | S09 |
| **Conduite du changement** |  | *change management* | Ensemble des actions (communication, formation, accompagnement) qui aident les utilisateurs à adopter une nouveauté. | S05 |
| **Conflit de fusion** |  | *merge conflict* | Situation où deux modifications touchent la même ligne et où Git demande un choix humain. | S10 |
| **Consentement** |  | *consent* | Accord libre, spécifique, éclairé et univoque, donné par un acte positif et retirable à tout moment. | S12 |
| **Contraste** |  | *contrast ratio* | Rapport entre la luminosité du texte et celle du fond ; il doit être d'au moins 4,5:1 pour du texte courant. | S06 |
| **Coût total de possession** | TCO | *total cost of ownership* | Coût complet d'une solution sur sa durée de vie : achat, options, exploitation, temps interne. | S11 |
| **Découpage du projet** | WBS | *work breakdown structure* | Découpage du projet en lots puis en tâches de plus en plus fines. | S02 |
| **Délégué à la protection des données** | DPO | *data protection officer* | Personne chargée de conseiller et de contrôler la conformité d'un organisme au RGPD. | S12 |
| **Dépôt** |  | *repository* | Ensemble de fichiers avec tout leur historique de modifications. | S10 |
| **Diagramme de Gantt** |  | *Gantt chart* | Tableau où chaque tâche est une barre placée dans le temps. | S02 |
| **Diagramme de Pareto** |  | *Pareto chart* | Classement des causes par importance, qui montre qu'une petite part des causes produit l'essentiel des effets. | S17 |
| **Disponibilité** |  | *availability* | Part du temps pendant laquelle un service est utilisable. | S17 |
| **Durée de vie d'une réponse DNS** | TTL | *time to live* | Temps, en secondes, pendant lequel une réponse peut rester en mémoire chez le demandeur. | S11 |
| **E-réputation** |  | *online reputation* | Image d'une organisation ou d'une personne sur Internet. | S14 |
| **Éco-conception de service numérique** |  | *digital eco-design* | Démarche qui réduit l'impact environnemental d'un service dès sa conception. | S15 |
| **Empreinte de clé** |  | *fingerprint* | Résumé court d'une clé, à comparer à la première connexion pour s'assurer qu'on parle au bon serveur. | S16 |
| **Engagement de niveau de service** | SLA | *service level agreement* | Accord écrit sur la qualité attendue d'un service : délais, disponibilité, plages de service. | S17 |
| **Enregistrement DNS** |  | *DNS record* | Ligne d'une zone : A (adresse), CNAME (alias), MX (messagerie), TXT (texte), NS (serveurs de noms). | S11 |
| **Épreuve de support et mise à disposition de services** | E5 |  | Épreuve orale de 40 minutes qui évalue le bloc 1 à partir du dossier numérique. | S19 |
| **Événement** |  | *event* | Ce qui se passe dans la page (saisie, clic, envoi) et auquel une fonction peut répondre. | S07 |
| **Expression régulière** |  | *regular expression* | Motif qui décrit un format de texte (courriel, date) pour le vérifier. | S07 |
| **Feuilles de style** | CSS | *cascading style sheets* | Langage qui décrit la présentation d'une page : couleurs, tailles, disposition. | S06 |
| **Flux de syndication de contenu** | RSS | *really simple syndication* | Fichier XML où un site publie la liste de ses derniers articles. | S18 |
| **Fonction pure** |  | *pure function* | Fonction dont le résultat ne dépend que de ses paramètres et qui ne modifie rien ailleurs ; elle est facile à tester. | S08 |
| **Fusion** |  | *merge* | Réunion des modifications d'une branche dans une autre. | S10 |
| **Gestion des appareils mobiles** | MDM | *mobile device management* | Outil qui inscrit, configure, contrôle et peut effacer à distance les terminaux mobiles. | S16 |
| **Identité numérique** |  | *digital identity* | Ensemble des traces et des profils d'une personne en ligne. | S14 |
| **Injection SQL** |  | *SQL injection* | Attaque qui glisse du code SQL dans une saisie collée telle quelle dans une requête. | S09 |
| **Interpréteur de commandes sécurisé** | SSH | *secure shell* | Protocole qui donne accès, de façon chiffrée, à la ligne de commande d'une machine distante et permet de créer des tunnels. | S16 |
| **Jalon** |  | *milestone* | Date clé d'un projet où l'on vérifie qu'un résultat est atteint. | S02 |
| **JavaScript** |  |  | Langage de programmation exécuté dans le navigateur, qui fait réagir la page. | S07 |
| **Journal d'accès** |  | *access log* | Fichier où le serveur web écrit une ligne par requête reçue. | S13 |
| **Langage de balisage de pages web** | HTML | *hypertext markup language* | Langage qui décrit la structure et le sens d'une page : titres, tableaux, formulaires. | S06 |
| **Langage de requêtes** | SQL | *structured query language* | Langage pour lire, ajouter, modifier et supprimer des données dans une base. | S09 |
| **Marge** |  | *float, slack* | Retard qu'une tâche peut prendre sans retarder le projet. | S02 |
| **Modèle objet du document** | DOM | *document object model* | Représentation en arbre de la page en mémoire, que JavaScript peut lire et modifier. | S07 |
| **Paire de clés** |  | *key pair* | Clé privée gardée secrète et clé publique placée sur le serveur, qui permettent de s'authentifier sans mot de passe. | S16 |
| **Partie prenante** |  | *stakeholder* | Personne ou groupe qui est concerné par le projet ou peut l'influencer : commanditaire, utilisateurs, direction, prestataire. | S01 |
| **Périmètre** |  | *scope* | Ce qui est inclus dans le projet, et ce qui n'y est pas. | S01 |
| **Plan de site** |  | *sitemap* | Fichier XML qui liste les pages d'un site à destination des moteurs de recherche. | S13 |
| **Politique d'envoi du courrier** | SPF | *sender policy framework* | Enregistrement TXT qui liste les serveurs autorisés à envoyer du courrier pour un domaine. | S11 |
| **Portfolio** |  | *portfolio* | Dossier qui rassemble les réalisations professionnelles et leurs preuves. | S18 |
| **Principe du moindre privilège** |  | *least privilege* | N'accorder à un compte que les droits strictement nécessaires. | S09 |
| **Protocole de gestion automatique de certificats** | ACME | *automatic certificate management environment* | Protocole qui permet d'obtenir et de renouveler un certificat automatiquement. | S11 |
| **Recette** |  | *acceptance* | Vérification, avec le client, que la livraison répond aux exigences prévues. | S05 |
| **Récit utilisateur** |  | *user story* | Une exigence écrite du point de vue de l'utilisateur : « En tant que…, je veux… afin de… ». | S03 |
| **Référencement naturel** | SEO | *search engine optimization* | Ensemble des pratiques qui rendent un site compréhensible et trouvable par les moteurs de recherche, sans achat de place. | S13 |
| **Référentiel général d'amélioration de l'accessibilité** | RGAA |  | Référentiel français de critères et de tests pour mesurer l'accessibilité d'un service numérique. | S15 |
| **Référentiel général d'écoconception de services numériques** | RGESN |  | Référentiel de critères d'éco-conception réparti en neuf familles (édition 2024). | S15 |
| **Registre des traitements** |  | *record of processing activities* | Document qui liste chaque traitement de données personnelles : finalité, données, base légale, durée, sécurité. | S12 |
| **Règles pour l'accessibilité des contenus web** | WCAG | *web content accessibility guidelines* | Règles internationales d'accessibilité des contenus web, base du RGAA. | S15 |
| **Régression** |  | *regression* | Comportement qui fonctionnait et qui ne fonctionne plus après une modification. | S08 |
| **Requête préparée** |  | *prepared statement* | Requête envoyée avec des marqueurs, les valeurs étant transmises à part : la saisie n'est jamais interprétée comme du code. | S09 |
| **Réversibilité** |  | *reversibility* | Possibilité de récupérer ses données et son service pour changer de prestataire. | S11 |
| **Sprint** |  | *sprint* | Période courte et fixe (une à quatre semaines) à la fin de laquelle on livre un résultat utilisable. | S03 |
| **Système de gestion de base de données** | SGBD | *database management system* | Logiciel qui stocke les données, les retrouve et les protège (MariaDB, par exemple). | S09 |
| **Système de noms de domaine** | DNS | *domain name system* | Annuaire d'Internet qui associe un nom lisible (bellevigne.example) à des adresses et à d'autres informations. | S11 |
| **Taux de respect** |  | *compliance rate* | Part des tickets traités dans le délai promis. | S17 |
| **Test automatique** |  | *automated test* | Programme qui compare le résultat réel d'un code au résultat attendu. | S08 |
| **Traceur** |  | *tracker* | Dispositif (cookie, stockage local, pixel) qui lit ou écrit des informations sur le terminal de l'utilisateur. | S12 |
| **Tunnel SSH** |  | *SSH tunnel* | Redirection d'un port à travers une connexion SSH chiffrée, pour joindre un service non exposé. | S16 |
| **Validation d'une modification** |  | *commit* | Enregistrement dans l'historique d'un ensemble de modifications, avec un message, un auteur et une date. | S10 |
| **Veille** |  | *monitoring* | Activité organisée de collecte, de tri et d'exploitation d'informations utiles. | S18 |
| **Vélocité** |  | *velocity* | Quantité de travail qu'une équipe termine en moyenne par sprint. | S03 |
| **Violation de données** |  | *data breach* | Perte, vol, destruction ou divulgation de données personnelles à un mauvais destinataire. | S12 |
| **Zone DNS** |  | *DNS zone* | Fichier qui contient les enregistrements d'un domaine, tenu par des serveurs qui font autorité. | S11 |
