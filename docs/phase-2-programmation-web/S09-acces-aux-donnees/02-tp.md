## Contraintes

- Travail **uniquement sur la machine virtuelle de laboratoire** (Debian ou Ubuntu avec Apache, PHP, extension PDO MySQL et MariaDB). Le mot de passe du compte `portail` est un identifiant de laboratoire.
- La page vulnérable ne sert **que** pour la démonstration ; elle n'est jamais installée sur un serveur accessible de l'extérieur.
- Les associations, adresses et dates sont **fictives**.

## Partie A – Créer et interroger la base (≈ 40 min)

1. Charge le schéma : `sudo mariadb < schema.sql`.
2. Crée un compte à droits limités :

```sql
CREATE USER 'portail'@'localhost' IDENTIFIED BY 'motdepasse-de-labo';
GRANT SELECT, INSERT ON portail.* TO 'portail'@'localhost';
FLUSH PRIVILEGES;
```

3. Écris et exécute les requêtes suivantes :

| N° | Besoin | Ta requête |
|---|---|---|
| 1 | Les salles de 50 places ou plus, de la plus grande à la plus petite | |
| 2 | Le nombre de réservations par salle le 15 mars 2030 | |
| 3 | Le nombre de **minutes** réservées par salle (toutes dates) | |
| 4 | Le créneau 10 h–12 h de la salle 1 le 15 mars 2030 est-il libre ? | |

**J'anticipe.** Que renvoie la requête 4 ? Et pour 11 h–12 h ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

1. `SELECT nom, capacite FROM salles WHERE capacite >= 50 ORDER BY capacite DESC;` → salle des fêtes (200), gymnase (120), salle d'exposition (60).
2. `SELECT s.nom, COUNT(*) FROM reservations r JOIN salles s ON s.id = r.salle_id WHERE r.jour = '2030-03-15' GROUP BY s.nom;` → salle des fêtes 2, salle du conseil 1.
3. `SELECT s.nom, SUM(TIME_TO_SEC(r.fin) - TIME_TO_SEC(r.debut)) / 60 FROM reservations r JOIN salles s ON s.id = r.salle_id GROUP BY s.nom;` → gymnase 120, salle des fêtes 210, salle du conseil 120.
4. `SELECT COUNT(*) FROM reservations WHERE salle_id = 1 AND jour = '2030-03-15' AND debut < '12:00' AND fin > '10:00';` → **1** (la réservation 9 h–11 h gêne : créneau non libre). Pour 11 h–12 h : `debut < '12:00' AND fin > '11:00'` → **0** : libre.

</details>

## Partie B – Les pages PHP (≈ 55 min)

1. Place `connexion.php` à côté de tes pages. Écris `reservations.php` : affiche, dans un tableau HTML, les réservations d'un jour (paramètre `jour`, par défaut le 15 mars 2030) avec le nom de la salle, l'association et les heures. **Requête préparée** ; affichage avec `htmlspecialchars`.
2. Écris `reserver.php` : reçoit le formulaire de S06 (méthode POST), **refait les contrôles** (nom, courriel valide, salle, format de date et d'heures, fin après début), **refuse un chevauchement** (code 409) et sinon **insère** la réservation (requête préparée).

**Tests.** Complète :

| Demande | Code attendu | Résultat obtenu |
|---|---|---|
| Salle 1, 15 mars 2030, 10:00 → 12:00 | | |
| Salle 1, 15 mars 2030, 11:00 → 12:00 | | |
| Nom vide, courriel « x », fin avant début | | |

**Je comprends.** Pourquoi `reserver.php` refait-il les contrôles déjà faits par `salles.js` (S07) ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

Tests : 10 h–12 h → **409** (« Ce créneau est déjà réservé ») ; 11 h–12 h → **200** (« Réservation enregistrée ») ; saisie invalide → **400** (« Demande invalide »). Le navigateur est **sous le contrôle de l'utilisateur** : il peut contourner `salles.js` ou envoyer une requête sans la page. Le serveur ne peut faire confiance qu'à **lui-même**.

</details>

## Partie C – L'injection SQL (≈ 40 min)

1. Installe `injection-vulnerable.php` (laboratoire uniquement). Appelle-la avec `?association=Chorale` : une ligne.
2. Appelle-la avec `?association=x' OR '1'='1` (adresse encodée par le navigateur). Que se passe-t-il ? ______________________
3. Explique **pourquoi** à partir de la requête finale construite : ______________________
4. **Corrige** la page avec une requête préparée et rejoue la même saisie : résultat ? ______________________
5. Avec le compte `portail`, essaie `DELETE FROM reservations;` puis un `INSERT` avec une fin avant le début : que répond la base ? ______________________

<details markdown="1">
<summary>Éléments de réponse</summary>

2. **Toutes** les réservations s'affichent, avec les courriels de tout le monde : fuite de données personnelles. 3. La requête devient `… WHERE association = 'x' OR '1'='1'` : la condition `'1'='1'` est toujours vraie. 4. Avec `prepare` et `execute([$association])`, la saisie est traitée comme **un texte** : aucune ligne ne correspond. 5. `ERROR 1142 : DELETE command denied` (moindre privilège) et `ERROR 4025 : CONSTRAINT failed` (contrainte `CHECK (fin > debut)`) : la base protège **aussi** quand le code se trompe.

</details>
